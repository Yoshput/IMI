# I SEE YOU MARKETING INTELLIGENCE
# DESIGN SYSTEM

Version: 1.0


# 01. DESIGN THESIS

Create a premium internal marketing intelligence application that feels designed by a product designer, not generated from a SaaS template.

The visual identity should communicate:

Precision
Confidence
Speed
Clarity
Intelligence
Modernity
Youthfulness

The interface should feel appropriate for a real marketing team presenting data to:

- management
- owner
- HRD
- finance
- marketing leadership


# 02. DESIGN DIRECTION

Primary direction:

Editorial Data Product

Secondary influence:

Apple-level interaction quality
iOS-level hierarchy
Linear-level product polish
Raycast-level density
Vercel-level restraint

Do not clone any of these products.

Use them only as quality references.


# 03. VISUAL PERSONALITY

The product should feel:

- bold
- premium
- sharp
- modern
- calm
- intelligent
- editorial
- confident
- Gen Z without becoming childish

It should NOT feel:

- corporate template
- generic SaaS
- crypto dashboard
- AI chatbot dashboard
- startup landing page
- gaming dashboard


# 04. DESIGN DIALS

ENERGY: 3/5
RHYTHM: 4/5
MOTION: 3/5

The interface should have personality but remain professional.

Do not turn the application into an animation showcase.


# 05. LAYOUT PHILOSOPHY

Use hierarchy instead of excessive cards.

Not every section needs a container.

Not every data point needs a card.

Prefer:

- editorial grouping
- strong whitespace
- dividers
- typography
- charts
- tables
- contextual panels

Use cards only when they create meaningful grouping.


# 06. IMPORTANT ANTI-SLOP DESIGN PRINCIPLE

Do not generate the statistically average SaaS dashboard.

Avoid:

- purple gradient hero
- blue-purple gradients
- generic centered hero
- excessive rounded cards
- glassmorphism everywhere
- excessive shadows
- identical cards
- three-column feature grids
- meaningless badges
- excessive pills
- default shadcn visual language
- generic Inter-only typography
- decorative blobs
- floating gradient shapes
- fake AI sparkle decorations
- unnecessary glow
- gradient text
- excessive animation


# 07. COLOR

Base should be neutral.

Background:

#F5F5F7

Surface:

#FFFFFF

Secondary surface:

#FAFAFA

Primary text:

#111111

Secondary text:

#6E6E73

Muted:

#86868B

Borders:

rgba(0,0,0,0.08)

The I See You brand accent should be used intentionally.

Do not introduce purple or indigo as a generic "AI color".

Do not use rainbow gradients.

Do not use gradient backgrounds unless there is a clear product reason.


# 08. TYPOGRAPHY

Do not automatically use Inter.

Select typography based on the visual direction.

Recommended approach:

Display:
a distinctive contemporary grotesk or premium sans.

Body:
high-legibility sans.

Optional:
a restrained editorial serif may be used for specific emphasis.

Typography must create hierarchy.

Avoid:

everything being 14–16px.

Important numbers should have obvious visual weight.


# 09. TYPOGRAPHIC SCALE

Hero metric:

48–72px

Large metric:

36–48px

Page title:

32–44px

Section:

22–28px

Body:

14–17px

Small:

12–13px


# 10. SPACING

Base unit:

8px

Primary spacing:

8
16
24
32
40
48
64
80

Do not use random spacing values unless necessary.


# 11. CORNERS

Use moderate radius.

Primary container:

16–20px

Small controls:

10–14px

Dialogs:

20–24px

Do not make every element extremely rounded.


# 12. DEPTH

Use subtle depth.

Preferred:

thin borders
very soft shadows
layer separation
background contrast

Avoid:

large blurry shadows
glowing containers
neon edges


# 13. DASHBOARD

The dashboard should NOT begin with a giant marketing hero.

Instead:

small context line

large title

time period

high-level performance

Example:

Marketing performance

Week 37
8–14 September 2026


# 14. KPI DESIGN

KPI should prioritize information.

Example:

FOLLOWERS

12,482

+4.2%

vs previous week

Include a small contextual trend visualization where useful.

Avoid 8 identical cards in a grid.


# 15. CONTENT ANALYTICS

Content should be treated as evidence.

Use:

ranked content
thumbnails
metrics
comparison
category
trend

A top-performing item should visually dominate weaker items.

Do not make every item visually equal.


# 16. TABLES

Tables are important because this is an internal reporting tool.

Tables should be:

dense but readable
keyboard accessible
sortable
filterable
responsive

Use visual hierarchy in important rows.

Do not turn every table row into a giant card on mobile.


# 17. CHARTS

Charts should communicate one idea.

Avoid decorative charts.

Prefer:

line
bar
area
ranked comparison

Use annotations when they help explain a change.

Do not overload charts with grid lines.


# 18. STORY RECAP

Story analytics should visually prioritize:

highest viewers
viewer trend
most discussed topic
most frequent question

Use ranked hierarchy.

Do not create a dozen identical cards.


# 19. COMPETITOR RADAR

Competitor monitoring should feel like a research workspace.

Show:

competitor
recent activity
format
topic
source
observed performance
notes

A research timeline can be used for historical observations.


# 20. TREND RADAR

Trend Radar should feel editorial and research-oriented.

Example:

POV TRY-ON

Observed across:
3 competitors

Momentum:
Rising

Opportunity:
High

Recommended adaptation:
...

Avoid fake futuristic "AI radar" visuals.


# 21. AI INSIGHTS

AI should NOT be visually represented with:

- glowing stars
- purple gradients
- floating sparkles
- robot illustrations
- excessive futuristic graphics

AI should feel like an analyst.

Use:

Insight
Evidence
Interpretation
Recommendation


# 22. AI COPY

Avoid:

"Unlock the power of..."
"Supercharge your..."
"Revolutionize..."
"Transform your..."
"Take your marketing to the next level..."

Use direct language.

Example:

"POV content generated 2.4× higher engagement than promotional content this week."


# 23. REPORT BUILDER

Report builder should feel like an editorial document workspace.

Structure:

Left:
sections

Center:
report

Right:
configuration

The report should visually resemble a professional internal report, not a dashboard screenshot.


# 24. MEETING MODE

Meeting mode should be the most visually refined screen.

Use:

large typography
large charts
minimal navigation
clear hierarchy
high contrast
restrained transitions

No dashboard clutter.

No unnecessary sidebar.

No excessive decoration.


# 25. MOTION

Use GSAP.

Motion should communicate:

- hierarchy
- transition
- causality
- feedback
- progress

Good:

page entrance
chart reveal
number interpolation
drawer transition
filter transition
report section transition

Bad:

everything fades upward
everything scales on hover
constant floating
parallax everywhere
bounce buttons
scroll-jacking


# 26. MOTION TIMING

Micro:

150–220ms

Standard:

250–400ms

Large:

450–700ms

Never make routine interactions feel slow.


# 27. HOVER

Hover should be subtle.

Do not:

scale buttons aggressively
bounce cards
rotate elements
add glowing borders

Use:

opacity
background shift
border shift
small translation


# 28. MOBILE

Mobile must not simply be desktop squeezed into a narrow viewport.

Recompose information.

Primary navigation:

Overview
Analytics
Reports
Trends
More

Complex tables can become horizontal-scroll regions.


# 29. ACCESSIBILITY

Support:

keyboard
focus
screen readers
reduced motion
sufficient contrast

Never communicate meaning only through color.


# 30. EMPTY STATES

Empty states must be useful.

Example:

No competitor observations yet.

Add your first competitor observation to start building the market history.

[Add Observation]


# 31. LOADING

Prefer skeleton states.

Skeleton structure should resemble final content.

Avoid generic centered spinners.


# 32. ERROR

Errors should explain:

what happened
why
what the user can do

Example:

Unable to load weekly report.

The data source did not respond.

[Retry]


# 33. RESPONSIVE

320px
390px
768px
1024px
1280px
1440px
1920px

Test all important layouts.


# 34. PERFORMANCE

Avoid:

large animation libraries for simple effects
unnecessary client components
huge image payloads
continuous animations

Prefer:

transform
opacity
CSS
GSAP only where justified


# 35. FINAL DESIGN TEST

Before accepting a page, ask:

1. Does this look like a template?
2. Could another AI generate the same page from "modern SaaS dashboard"?
3. Are there too many cards?
4. Is there unnecessary glassmorphism?
5. Is the hierarchy obvious?
6. Does every animation have a purpose?
7. Does every color have a reason?
8. Is the content driving the composition?
9. Does the page feel specific to I See You?
10. Would this look credible in front of an owner or manager?

If the answer to #1 or #2 is yes:

redesign the page.


# 36. QUALITY BAR

The product should feel like:

a real internal product built by a strong product design team.

Not:

a generated demo.

Not:

a template.

Not:

an AI showcase.
