# I SEE YOU MARKETING INTELLIGENCE
# ANTI-SLOP UI / UX GUARDRAILS

Version: 1.0

This file is a quality filter.

It does not replace DESIGN.md.

DESIGN.md defines the visual direction.

ANTISLOP.md prevents generic AI-generated output.


# 01. PRIMARY OBJECTIVE

The interface must NOT look obviously generated by an AI coding agent.

It must look:

intentional
specific
designed
contextual
credible
product-driven

The goal is not to be weird.

The goal is to be intentional.


# 02. ZERO-TOLERANCE AI SLOP PATTERNS

Do not use these as default patterns.

## Color

Do not use:

- purple-to-blue gradients
- indigo-to-violet gradients
- generic AI purple
- neon purple glow
- rainbow gradients
- gradient text
- blue/purple AI glow

unless the brand or data meaning explicitly requires it.


# 03. NO GENERIC AI SYMBOLS

Do NOT use decorative AI symbols as visual decoration.

Especially avoid:

- sparkle symbols
- four-point AI stars
- magic wand icons
- generic robot icons
- brain icons
- glowing neural-network graphics
- "AI magic" symbols
- floating stars around AI text

AI features should be represented through typography, information hierarchy, and useful interaction.

Not decorative symbols.


# 04. NO EMOJI-DRIVEN UI

Do not use emojis as UI decoration.

Do not create:

"🔥 Trending"

"🚀 Growth"

"✨ AI Insight"

"💡 Smart Recommendation"

"📈 Analytics"

"🎯 Strategy"

Use proper UI labels instead.

Examples:

TRENDING
GROWTH
AI INSIGHT
RECOMMENDATION
ANALYTICS
STRATEGY

Emoji may exist inside user-generated content if the actual data contains it.

Never introduce emojis merely to make the interface look lively.


# 05. NO AI-SLOP COPY

Never generate filler such as:

"Unlock the power of..."
"Supercharge your..."
"Transform your..."
"Revolutionize..."
"Elevate your..."
"Take your marketing to the next level."
"Powerful insights at your fingertips."
"Your all-in-one solution."
"Built for the future."
"Next-generation intelligence."

Write direct language.

Bad:

"Unlock powerful marketing intelligence."

Good:

"Marketing performance, competitor activity, and weekly insights."


# 06. NO GENERIC HERO

Internal dashboard pages must NOT use:

centered headline
gradient background
subtitle
two CTA buttons
floating dashboard screenshot

This is a marketing landing-page pattern.

The dashboard should immediately show useful information.


# 07. NO CARD WALL

Do not put every piece of information inside a rounded card.

Do not create:

8 KPI cards
3 feature cards
4 insight cards
3 action cards

all with identical:

radius
padding
shadow
border

Use hierarchy.


# 08. CARD PURPOSE TEST

Before creating a card ask:

"What relationship does this container communicate?"

If the answer is:

"Because dashboards usually use cards."

Do not create it.


# 09. NO IDENTICAL GRID

Avoid:

3 identical cards
4 identical cards
6 identical cards
9 identical cards

unless the data genuinely requires a grid.

Different information should have different visual weight.


# 10. NO GLASSMORPHISM BY DEFAULT

Do not use:

backdrop-blur
frosted glass
translucent panels
glowing borders

as the default visual language.

Glass may only be used when it has a real spatial or interaction purpose.


# 11. NO EXCESSIVE SHADOW

Do not use:

shadow-2xl
heavy floating shadows
glowing shadows

on every component.

Depth should come from:

spacing
contrast
border
layering


# 12. NO EXCESSIVE ROUNDING

Do not use:

rounded-full everywhere
rounded-3xl everywhere
rounded-2xl everywhere

Use radius according to component type.

Buttons may be rounded.

Cards may be rounded.

Tables do not need to look like pills.


# 13. NO BADGE ABUSE

Do not turn every label into:

[ TREND ]
[ HIGH ]
[ NEW ]
[ ACTIVE ]
[ AI ]
[ SMART ]

Badges should communicate meaningful state.

Not decoration.


# 14. NO GENERIC AVATAR DESIGN

Do not generate random colorful initials avatars just to fill empty UI.

If avatars are unavailable:

use name
role
or a neutral placeholder.


# 15. NO DECORATIVE BLOBS

Do not add:

gradient blobs
floating circles
abstract blobs
background waves
random geometric shapes

unless the visual concept explicitly requires them.


# 16. NO FAKE FUTURISM

Avoid:

neon dashboards
cyberpunk
glowing grids
holographic cards
3D floating panels
futuristic HUDs

This is a professional marketing intelligence system.

Not a sci-fi interface.


# 17. NO TEMPLATE DASHBOARD

Do not reproduce the typical:

sidebar
topbar
4 KPI cards
large chart
3 cards
recent activity

layout automatically.

The information architecture should be driven by the marketing workflow.


# 18. DATA-FIRST COMPOSITION

Content should determine visual hierarchy.

If one metric matters more:

make it larger.

If one content item dominates:

make it visually dominant.

If a table is more useful:

use a table.

Do not force every dataset into cards or charts.


# 19. CHART PURPOSE TEST

Every chart must answer a question.

Examples:

"What changed over time?"

"Which branch performed best?"

"Which content category performs best?"

"How did follower growth change?"

If the chart does not answer a useful question:

remove it.


# 20. NO DECORATIVE CHARTS

Do not use:

fake waveforms
random radial charts
unnecessary radar charts
donut charts for trivial percentages
charts with no data meaning

Especially do not use radar charts merely because the feature is called "Radar".


# 21. NO MEANINGLESS MOTION

Do not apply:

fade-up to every section
slide-up to every card
scale-up to every button
bounce effects
constant floating
parallax everywhere

Animation must have purpose.


# 22. NO AUTOMATIC SCROLL ANIMATION

Do not make every section animate when entering viewport.

Use motion selectively.

Prioritize:

page transitions
data changes
chart reveal
drawer transitions
filter changes


# 23. NO HOVER SCALE ABUSE

Do not:

scale buttons to 1.05
scale cards to 1.05
bounce cards

for every hover.

Use subtle feedback instead.


# 24. NO AI-GENERATED VISUAL FILLER

Never add UI simply because the page "looks empty."

Whitespace is acceptable.

Empty space can establish hierarchy.


# 25. NO FAKE SOCIAL PROOF

Do not invent:

user counts
followers
reviews
customer quotes
performance statistics

Seed data must be explicitly marked as demo data.


# 26. NO FAKE ANALYTICS

Never invent a number because a chart needs data.

Never fabricate:

followers
views
engagement
competitor metrics
ROI
conversion

Use:

empty state
mock state
or explicit demo data.


# 27. SOURCE TRANSPARENCY

Every analytics value must have a known source.

Possible:

manual
csv
xlsx
google sheets
api

Do not claim "live" unless the source is actually live.


# 28. NO DEFAULT FONT WITHOUT THINKING

Do not automatically choose Inter simply because it is available.

Typography must be an intentional design decision.

If using Inter is appropriate:

document why.

Otherwise choose a more suitable typography system.


# 29. NO DEFAULT SHADCN LOOK

Do not ship raw default shadcn styling as the visual identity.

shadcn may provide primitives.

The final product must have its own:

typography
spacing
radius
density
states
composition


# 30. NO GENERIC ICON LANGUAGE

Do not mix:

Lucide
Heroicons
Font Awesome
random SVG
emoji

without a coherent icon system.

Choose one icon language.

Use icons only when they improve recognition.


# 31. NO ICON-FIRST DESIGN

Do not design a section around an icon.

Design around the information.

Icon comes second.


# 32. PURPOSE GATE

Any potentially "sloppy" technique can be used only when the agent can explain:

1. What problem does it solve?
2. Why is it appropriate here?
3. Why is this better than the simpler alternative?

If no clear answer exists:

remove it.


# 33. DESIGN INTENT

Before implementing a new UI page, define:

VISUAL THESIS

HIERARCHY

DENSITY

PRIMARY ACTION

MOTION PURPOSE

Do this before writing components.


# 34. CONTENT-DRIVEN DESIGN

Do not design the interface with placeholder text and assume the final content will fit.

Marketing reports contain:

long titles
branch names
dates
metric values
notes
observations
URLs

Design for realistic content.


# 35. LONG CONTENT TEST

Test:

very long content title
very long competitor name
large number
small number
empty value
missing image
missing metric

The UI must remain stable.


# 36. EMPTY STATE TEST

Every data module must handle:

zero records
one record
many records
missing data

Never leave blank white space without explanation.


# 37. RESPONSIVE TEST

The UI must be evaluated at:

390px
768px
1024px
1440px

Responsive design must recompose the layout.

Do not simply shrink desktop.


# 38. ACCESSIBILITY FLOOR

Do not sacrifice:

contrast
keyboard navigation
focus states
semantic structure
reduced motion

for visual style.


# 39. MOTION FLOOR

Respect:

prefers-reduced-motion

When enabled:

disable decorative motion
reduce transitions
remove parallax
avoid animated counters if unnecessary


# 40. FINAL SLOP AUDIT

Before shipping any UI, perform:

A. COLOR CHECK

Is there unnecessary purple/indigo?

B. CARD CHECK

Are there too many cards?

C. TYPOGRAPHY CHECK

Does the type system feel intentional?

D. MOTION CHECK

Is anything moving without purpose?

E. ICON CHECK

Are icons communicating something?

F. COPY CHECK

Does the text sound like AI marketing copy?

G. DATA CHECK

Are metrics real or explicitly demo?

H. HIERARCHY CHECK

Can the user immediately identify what matters?

I. RESPONSIVE CHECK

Does the layout recompose correctly?

J. PRODUCT CHECK

Does this feel specific to I See You Marketing Intelligence?

# 42. MOST IMPORTANT RULE

Do not fight AI slop by making the interface bizarre.

Do not use brutalism simply to be different.

Do not remove every rounded corner.

Do not remove every animation.

Do not choose strange typography merely to look unique.

The objective is:

INTENTIONAL DESIGN.

Not:

RANDOM DESIGN.
